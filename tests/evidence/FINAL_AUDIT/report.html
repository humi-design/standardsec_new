2. Fixes applied — detail by area

2.1 Structure and semantics

Finding 8.1 — heading hierarchy (1.3.1 A). Every page now has exactly one visible H1 describing its main topic, with no skipped levels. Duplicate hero H1s on the homepage and the six product templates were removed so that simultaneously rendered slides do not expose two level-1 headings. Statistic values that were marked up as headings — #1, ~30ms, 0.0 — were converted to styled paragraphs, because they do not describe a section. Repeated service blocks were normalised to a consistent heading level.

<!-- before: a statistic exposed as a heading, breaking the outline -->
<h3 class="in-counter">#1</h3>

<!-- after: a paragraph with the same visual styling, correct semantics -->
<p class="in-counter">#1</p>

Finding 8.16 — duplicate IDs (4.1.1 A, historical). The duplicate-ID scan of the rendered DOM returns zero duplicates on all 32 pages, and all for/aria-labelledby/ aria-describedby/fragment references resolve. Note that SC 4.1.1 Parsing was removed in WCAG 2.2; it is retained here only for historical traceability, and any residual effects are assessed under 4.1.2 and 1.3.1. The duplicate mobile/desktop navigation markup and the language-switch controls were specifically checked.

Finding 8.10 — page titles (2.4.2 A). All 32 pages carry unique, descriptive titles of the form "Page Name | Standard Securities". The one duplicate pair found during this audit (complaint.html and complaint_new.html) was corrected. The complete page-title inventory is in Deliverable D.

2.2 Forms, labels and validation

Finding 8.2 — contact form labels (1.3.1 A / 2.4.6 AA / 3.3.2 A). The Contact form fields previously relied on placeholder text alone. Each field now has a visible <label for> programmatically associated with its control, an sr-only "(required)" marker, help text wired through aria-describedby, and both required and aria-required. Placeholders are retained as supplementary hints, never as the sole identifier.

<label for="email">Email Address <span class="sr-only">(required)</span></label>
<input id="email" name="email" type="email" autocomplete="email"
       required aria-required="true"
       aria-describedby="email-help" placeholder="you@example.com">
<p id="email-help" class="uk-text-meta">We reply within two working days.</p>

Finding 8.3 — autocomplete (1.3.5 AA). Every non-button input across the Create-Account, Contact, Sign-In and complaint forms was enumerated with its autocomplete value. The correct standardised tokens are present on the right controls — name, email, tel, username, current-password — with no inappropriate tokens assigned.

Finding 8.15 — error identification and suggestion (3.3.1 A / 3.3.3 AA, 4.1.3). Both forms were driven with empty, malformed and valid input in the local environment only.

2.3 Navigation, keyboard and focus

Finding 8.7 — hamburger menu and keyboard navigation (1.4.10, 1.4.13, 2.1.1, 2.4.5). The menu opens and closes by pointer and by keyboard (Enter and Space) at every tested width; aria-expanded flips false↔true in step with the real modal state and the button's label changes between "Open mobile navigation menu" and "Close mobile navigation menu". Escape closes the menu and returns focus to the toggle. All primary navigation items — including About Us, Login, Quick Links, KYC and Complaints — are reachable. The navigation breakpoint was confirmed to sit between 895 px (hamburger shown) and 960 px (desktop row).

// js/a11y-nav.js — the toggle's ARIA state tracks the real modal state
var sync = function () {
    var open = modal.classList.contains('uk-open');
    toggle.setAttribute('aria-expanded', open ? 'true' : 'false');
    toggle.setAttribute('aria-label', open ? 'Close mobile navigation menu'
                                           : 'Open mobile navigation menu');
};
['show', 'shown', 'hide', 'hidden'].forEach(function (name) {
    modal.addEventListener(name, sync);
});

Finding 8.9 — skip link (2.4.1 A). On all 32 pages the "Skip to main content" link is the first tab stop, becomes visible on focus (measured at top: 10px; left: 10px, 189 × 43 px), carries a 3 px #0b4c8c outline, and its target #main-content exists. Pressing Enter moves the document hash to the main region.

Finding 8.11 — visible focus (2.4.7 AA). Focus was applied with a real keyboard, not merely inspected in the stylesheet. Every keyboard-focusable control — skip link, navigation links and buttons, the hamburger toggle, language control, account-opening and fund-transfer controls, form inputs and submit buttons, footer links, ticker and scrolling-notice controls, carousel controls and the accessibility toolbar — shows a 3 px solid rgb(11, 76, 140) outline that is distinguishable from the unfocused state and not clipped.

2.4 Motion, contrast, resize and text spacing

Finding 8.8 — pause, stop, hide (2.2.2 A). The hero slideshow was observed over an 8-second window: it renders a single slide and its transform never changes, so it is static and no carousel pause control is required. The price ticker autoplays and its control was driven end to end — pausing sets aria-pressed="true" and freezes the transform, resuming sets aria-pressed="false" and restarts autoplay. Under prefers-reduced-motion: reduce the scrolling notices start paused.

3. Navigation alignment regression — root cause and fix

A separate regression was reported after the accessibility work: the primary navigation split across two uneven rows (Home / Products / Contact / Complaints on row 1; About Us / Login / Quick Links / KYC on row 2) with inconsistent spacing. Two pre-existing rules in css/accessibility-fixes.css combined to cause it.

3.1 Cause A — the 1.4.12 text-spacing override reached the menu

The text-spacing block is deliberately broad so it survives a user-origin override:

p, li, td, th, label {
    line-height: 1.5 !important;
    letter-spacing: 0.12em !important;   /* 1.92px at 16px */
    word-spacing: 0.16em !important;     /* 2.56px at 16px */
}

.uk-navbar-nav is a <ul>, so every menu <li> matched. At the template's 16 px menu font size that added roughly 1.92 px of tracking and 2.56 px of word spacing to each of the eight labels, widening the bar from 836 px to 952 px — a 14 % increase. The desktop bar appears at min-width: 960px, but its container is narrower than 952 px until roughly 1100 px viewport width, so the links wrapped.

3.2 Cause B — flex-wrap: wrap on the menu

The rule header .uk-navbar-nav { flex-wrap: wrap } (added for the 1.4.4 resize-text work) allowed the items to wrap instead of overflowing, so the width overflow from Cause A became two unordered rows rather than a scrollbar. Wrapping a horizontal menu reorders the visual sequence relative to DOM order, which is a 1.3.2 Meaningful Sequence and 2.4.3 Focus Order risk.

WidthBeforeAfter
960 px2 rows — contentW 952 > navW 8501 row — 836 = 836
1024 px2 rows — 952 > 9141 row, no overflow
1100–1920 px1 row1 row (unchanged)

3.3 The fix

/* css/accessibility-fixes.css — navigation is UI chrome, not prose.
   The 1.4.12 tracking above is meant for flowing text, but it also matched the
   menu's `li` elements and inflated the horizontal menu from 836px to 952px. */
.uk-navbar-nav, .uk-navbar-nav li, .uk-navbar-nav li > a,
.uk-nav, .uk-nav li, .uk-nav li > a,
.uk-nav-sub, .uk-nav-sub li, .uk-nav-sub li > a {
    letter-spacing: normal !important;
    word-spacing: normal !important;
}

header .uk-navbar-nav {
    flex-wrap: nowrap;   /* was: wrap — cannot break into unordered rows */
}

The 1.4.12 text-spacing support is kept for prose; only the menu chrome is exempt. An overflow-x: auto fallback on the nav container was tested and rejected, because a hit-test showed it clips the dropdowns — the "History" item became unhittable.

3.4 Robustness under extreme text enlargement

Because nowrap would clip links if text grew far beyond the normal size, a guard was added to js/a11y-nav.js for WCAG 1.4.4. When the links grow wider than the container, the bar collapses into the same accessible hamburger menu used at narrow viewports, instead of clipping. It is re-evaluated on resize, after web-font load, and — because the in-page A+/A− control changes the root font size without firing a resize event — through a MutationObserver on the root element's style attribute.

var overflowing = navList.scrollWidth > navBar.clientWidth + 1;
if (overflowing) {
    navBar.style.display = 'none';
    // keep the flex layout, but beat uikit's `.uk-hidden\@m { display:none !important }`
    mobileBar.style.setProperty('display', 'flex', 'important');
} else {
    navBar.style.removeProperty('display');
    mobileBar.style.removeProperty('display');
}

7.1 Final verdict

FIXES APPLIED BUT PARTIALLY UNVERIFIED. All 17 findings are remediated and independently re-tested at the level this environment supports, with zero automated violations, zero duplicate IDs, zero missing alternatives, unique titles, working skip links and focus indicators, functioning mobile navigation, motion controls, form validation and a working language switch. The outstanding items are the four manual checks above, which need a different environment or client-side staging access.

Production safety: no commit to main, no merge, no deployment and no production configuration change was made during remediation; no client, investor, banking, KYC or personal data was submitted; no real message was sent through the Contact or Newsletter forms. All testing used a local static server with clearly identified test data. Existing user changes were preserved — no reset, revert or destructive Git operation was performed.
Scope note: this report documents remediation and verification work performed against the local working tree and the two pull requests listed in Section 6. It is not a certification of conformance.
